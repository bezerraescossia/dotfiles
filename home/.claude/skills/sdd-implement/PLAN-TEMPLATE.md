## Phase 0 — Research (conditional)

If any `NEEDS CLARIFICATION` remains in the Technical Context, generate `research.md`: for each unknown, a research task ("Research {unknown} for {feature context}"); for each technology/modeling choice, a best-practices task. Consolidate findings as `Decision` / `Rationale` / `Alternatives considered`. The final `plan.md` must not contain any `NEEDS CLARIFICATION` without a corresponding resolved entry here.

## Phase 1 — Design & Contracts (conditional)

Prerequisite: `research.md` complete (if needed).

- **`data-preparation.md`**: if Business & Data Understanding is non-trivial — data sourcing, versioning scheme, train/validation/test split strategy and why, leakage checks.
- **`data-model.md`**: if "Key Entities" is non-trivial — entity names, fields, relationships, validation/state-transition rules. If the feature belongs to an epic with a `shared-data-model.md`, reference those entities instead of redefining them.
- **Contract file(s)**: if the feature exposes an interface (prediction API, batch-scoring contract, prompt/response schema, CLI) — one flat file per contract (e.g. `artifact-schemas.md`, `openapi.yaml`), no `contracts/` subfolder.
- **`quickstart.md`**: a runnable validation guide — prerequisites, setup, run/train/eval commands, expected outcomes. Reference the other artifacts instead of duplicating them; no full implementation code or test suites here.
